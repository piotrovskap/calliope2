The Core Rule — Dealer Isolation

Non-negotiable. Specified in the kickoff meeting and enforced at every layer of the CDP.

"We have multi-tenancy. So we can have 100 clients of ours and Mike as a customer could be at three of our clients' locations. We want one Mike Paylor — but the attributes of Mike Paylor are specific to a property. If Mike comes to my dealership and gives me a phone number and then goes to Alex's dealership and gives an email — as a CDP we should be able to see everything — but me as the client of dealership A, I should only be able to see the attributes that Mike gave me, not the ones he gave the other dealership. We can't cross-pollinate. We can't use one dealer's data to benefit another dealer. There's a conflict of interest even if both dealers are our clients." — Dan Aston, SVP Engineering, DAS Technology · Kickoff meeting, May 27 2026

✕ No cross-pollination. One dealer's data cannot benefit another dealer — even if both are DAS clients. This is a conflict of interest. The architecture enforces it at three layers:
Layer 1 — Database
PostgreSQL RLS
Every table with dealership data has a dealership_id column. RLS policies block any row that doesn't match the session's tenant.
Non-negotiable per decisions.md
Layer 2 — API
Tenant Middleware
Every API request extracts dealership_id from the JWT. Unscoped queries are bugs — flagged in CLAUDE.md.
Auth check on every endpoint, first line
Layer 3 — Frontend
Dealer Portal
The dealer portal shows only consumers linked to that dealership. Attributes filtered to what they contributed + shared third-party data (e.g. recalls).
Separate portal from DAS admin dashboard

DAS CDP — Open Decisions

Six decisions on the table. Five resolved, one needs sign-off before Phase 1 build begins.

D-1 OIDC / Auth Provider Resolved
✓ Auth0 Already in approved DAS tech stack
Keycloak Self-hosted, ops overhead
Azure Entra ID Would lock to Azure
AWS Cognito Retained as AWS-native fallback (not rejected)
Decision: Auth0 is pre-approved. Already in DAS stack alongside Kong, RabbitMQ, Redis, Azure Event Hubs. No new vendor approval needed.
D-2 Object Storage Target Resolved
✓ AWS S3 AWS-native raw landing (bronze) · SSE-KMS · replayable
Azure Blob Off the table — no Azure infra initially
Cloudflare R2 Not the chosen path
Decision: AWS S3 (SSE-KMS) for raw landing (bronze), per the AWS-native architecture — no Azure infra initially; proprietary stores stay portable behind interfaces.
D-3 consumer_attribute Scoping Needs Sign-off
Dan Aston established the rule in the kickoff meeting: "We can't cross-pollinate. We can't use one dealer's data to benefit another dealer." This decision maps that rule across the record's attribute categories (starting from Field Catalog v1 — the initial 27, which grows by design) — which attributes are DAS-global (visible across dealers, e.g. recalled VIN affects every owner) vs dealer-scoped (private to the contributing dealership). The choice per category directly generates the tenant-isolation policies written in the Phase 1 build.

✓ Django (Python) DRF REST + Strawberry GraphQL · Boilerworks base · unifies with Airflow/Temporal

Decision: Python/Django (DRF + Strawberry GraphQL) on a Boilerworks base, Go for performance-critical hot paths — batteries-included migrations, native GraphQL, one ecosystem with Airflow/Temporal.
D-5 Juicebox Replacement Resolved · 2026-06-14
✓ Apache Superset headless/embedded engine · open-source · self-host · $0 license · per-tenant guest-token + RLS
Metabase Pro optional · best non-technical authoring · per-seat cost at fan-out scale
Custom-build · Evidence.dev documented alternatives for the customer-facing layer
Power BI DAS has access · no internal devs (staffing-constrained)
Context: Juicebox runs 221 reports for 1,728 clients today but DAS confirmed it is not on the long-term roadmap. It cannot do SQL joins (all pre-joining happens in DWRPT). The CDP can feed DWRPT and leave Juicebox alone during migration. Decision: Apache Superset run as a headless/embedded engine on an open, self-hosted baseline; Metabase Pro optional. Alternatives documented so the client can trade license cost for delivery speed. Does not block Phase 1.
