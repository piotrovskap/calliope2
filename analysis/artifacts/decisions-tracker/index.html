D-3 · consumer_attribute Scoping
D-3
Resolved · 2026-06-21
Two-type classification — DAS-global vs Dealer-scoped, enforced by RLS
Dan Aston established the rule at the kickoff: "We can't cross-pollinate. We can't use one dealer's data to benefit another dealer." Decided: every record carries one of two data types — DAS-global (shareable across dealers) or dealer-provided (isolated per dealer) — classified by data provenance at ingestion time. Enforcement is PostgreSQL Row-Level Security (confirmed 2026-06-21 as the multi-tenant isolation mechanism): the identity graph resolves across tenants in a privileged role above RLS, while attribute/event facts stay tenant-scoped; visibility is computed from per-fact provenance (a set, not an owner). The category table below maps Field Catalog v1 (the initial 27, which grows by design) onto the two types.

D-5 · Juicebox Replacement
D-5
Resolved · 2026-06-14
Apache Superset (headless/embedded engine) — Metabase Pro optional
Juicebox is not on DAS's long-term roadmap (no SQL joins; all pre-joining happens in DWRPT). The CDP can feed DWRPT and leave Juicebox alone during migration; for the post-CDP reporting layer the decision is Apache Superset run as a headless/embedded engine on an open, self-hosted baseline, with Metabase Pro as an optional add-on. Custom-build and Evidence.dev evaluated as alternatives.
✓ Superset headless/embedded engine open-source · self-hosted · $0 license · per-tenant guest-token + RLS · dashboards-as-code
Metabase Pro optional add-on · best non-technical authoring · per-seat cost at fan-out scale
Custom-build · Evidence.dev documented alternatives for the customer-facing layer
Decision: Superset-as-engine open baseline; Metabase Pro optional. Does not block Phase 1. Full comparison in the Reporting Strategy artifact.
