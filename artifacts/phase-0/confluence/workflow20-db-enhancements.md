New tables and stored procedures were added to OLTP to support Workflow 2.0 functionality.  As much as possible, I tried to stay within the confines of RL's naming paradigms and nomenclature.  They are as follows:

# **Tables**

## franchise_excluded_lead_sources

This is where all excluded sources for franchises (and their respective desired processing actions) are stored.  Items in this table should be **inserted** and **modified** using the *franchise_excluded_lead_sources_upsert* stored procedure, which validates data prior to insertion/creation.  Items from this table can be queried manually, OR you can use the *franchise_excluded_lead_sources_reader* stored procedure, which can either return data for a single franchise ID or an entire list of all excluded sources for all franchise IDs.  The schema is as follows:

<div class="table-wrap">

|  |  |  |  |  |  |
|----|----|----|----|----|----|
| **id (uniquekey autoincrement int)** | **franchise_id (int)** | **lead_source (varchar50)** | **processing_action (varchar50)** | **date_created (datetime)** | **creator (varchar50)** |
| The ID of the source | The franchise ID the sources is being excluded from | Lead source verbiage that we want to use as a predicate | Desired processing action | Date created | Name of the person that created the new source |

</div>

## franchise_excluded_lead_sources_papertrail

This is where records of changes made to existing items are stored.  Nothing should ever manually be inserted into this table, as papertrail items are generated by the *franchise_excluded_lead_sources_upsert* calling *franchise_excluded_lead_sources_papertrail_upsert* with the proper validated parameter values.  Items can be viewed by querying the table manually, OR by using the *franchise_excluded_lead_sources_papertrail_reader* stored procedure.

<div class="table-wrap">

|  |  |  |  |  |  |  |
|----|----|----|----|----|----|----|
| **id (int)** | **before_source (varchar50)** | **after_source (varchar50)** | **before_processing_action (varchar50)** | **after_processing_action (varchar50)** | **modification_date (datetime)** | **modifier (varchar50)** |
| The ID of the source | Pre-update lead source | Post-update lead source | Pre-update processing action | Post-update processing action | Date of modification | Name of the person that did the modification |

</div>

# **Relationships:**

\[franchise_excluded_lead_sources\].\[id\] = \[franchise_excluded_lead_sources_papertrail\].\[id\]

- \[franchise_excluded_lead_sources\].\[id\] is a unique, auto-incrementing integer key.

- \[franchise_excluded_lead_sources_papertrail\].\[id\] is just an integer, and multiple items for a given ID can exist in this table (as an infinite number of updates can be made to a given source ID).

# **Stored Procedures:**

- franchise_excluded_lead_sources_reader

- franchise_excluded_lead_sources_upsert

- franchise_excluded_lead_sources_papertrail_reader

- franchise_excluded_lead_sources_papertrail_upsert

# **Stored Procedures (Detailed)**

## **franchise_excluded_lead_sources_reader**

**General Info:**

Used for pulling data from the *franchise_excluded_lead_sources* table.  Default constraint mandates that a franchise ID be supplied to prevent unintentional pulling of extra data from calls within the code, but this can be overidden manually, as explained below.

**Parameters:**

- *@franchise_id - \[Semi-optional\] The franchise ID that the sources have been excluded for.  Cannot be null unless @pull_all_franchises is set to 1.  This is to prevent code calls from inadvertently pulling an entire list of sources by inadvertently not supplying a franchise ID.*

- *@pull_all_franchises* - \[Optional\] Only for manual use.  Allows the SP to pull a full list of excluded sources.  Defaults to 0 (off).  Setting it to 1 enables it.

**Usage Examples:**

<u>Pull a list of all sources for all franchises:</u>  exec franchise_excluded_lead_sources_reader @pull_all_franchises

<u>Pull all sources for a given franchise:</u>  exec franchise_excluded_lead_sources_reader @franchise_id = 100001

## **franchise_excluded_lead_sources_upsert**

**General Info:**

Used for adding, modifying, and deleting sources from the *franchise_excluded_lead_sources* table.  Any call that modified or deletes a source also records a transaction in the franchise_excluded_lead_sources_papertrail table by way of the franchise_excluded_lead_sources_papertrail_upsert stored procedure.

**Parameters:**

- *@delete* - \[Optional\] Flag 1 to delete specified parser ID, otherwise omit the parameter from the SP call entirely.  Required an ID to be specified as well.

- *@id* - \[Semi-optional\] The ID of the source.  Supply one to update (or delete, as mentioned before) an existing source.  Omit if creating a new source.

- *@lead_source* - \[Semi-optional\] Verbiage that references the source that we want to specify the processing action for.  Can be supplied if updating or adding a new parser.  Can me omitted if updating, so long as @processing_action is supplied.  This would be done if you were changing the processing action but leaving the source verbiage the same.

- *@processing_action* -  \[Semi-optional\] The processing action we want to use for leads that include verbiage contained in the lead_source field.  Can be omitted, so long as lead_source is supplied.  This would be done if you were only updating the lead source verbiage.

- *@creator* - \[Optional\] The name of the person doing the upsert.  Defaults to the name of the system user if nothing is supplied.  Front end should supply this based on who is logged in to Extranet.

**Usage Examples:**

<u>Create new source:</u>  exec franchise_excluded_lead_sources_upsert @franchise_id = 100000, @lead_source = 'TrueCar', @processing_action = 'Pass Through'

<u>Update existing source:</u>  exec franchise_excluded_lead_sources_upsert @id = 100, @lead_source = 'TrueCar', @processing_action = 'Pass Through'

<u>Update existing source 2:</u>  exec franchise_excluded_lead_sources_upsert @id = 100, @lead_source = 'TrueCar'

<u>Update existing source 3:</u>  exec franchise_excluded_lead_sources_upsert @id = 100, @processing_action = 'Pass Through'

<u>Delete source:</u>  exec franchise_excluded_lead_sources_upsert @id = 100, @delete = 1

## **franchise_excluded_lead_sources_papertrail_reader**

**General Info:**

Used for pulling papertrail items for a given source ID.  Every time a source is updated (or when it gets deleted), a record of the transaction--along with what changed--gets recorded into the franchise_excluded_lead_sources_papertrail table, which is what this stored procedure reads from.

**Parameters:**

- *@id* - \[Required\] The ID of the source you'd like to view the history of.

**Usage Examples:**

<u>Pull records for an ID:</u>  exec franchise_excluded_lead_sources_papertrail_reader @id = 5

## **franchise_excluded_lead_sources_papertrail_upsert**

**General Info:**

Used for inserting papertrail records for changes made to excluded lead sources.  Should generally never be used manually.  It gets called almost automatically when doing an update to a source using the franchise_excluded_lead_sources_upsert SP.  A variety of parameters

**Parameters:**

- *@id* - \[Required\] ID of the source being updated.

- *@before_source* - \[Required\] Pre-modification lead source.

- *@after_source* - \[Required\] Post-modification lead source.

- *@before_processing_action* - \[Required\] Pre-modification processing action.

- *@after_processing_action* - \[Required\] Pre-modification processing action.

- *@modifier* - \[Required\] Name of the user making the modification.

**Usage Examples:**

*It isn't recommended to use this stored procedure manually.  It should be called by another stored procedure that supplies all of the necessary validated values.*

<u>Log a new papertrail item for a given source:</u>  exec franchise_excluded_lead_sources_papertrail_upsert @id = 4, @before_source = 'TrueCar', @after_source = 'TrueCar/USAA', @before_processing_action = 'Pass', @after_processing_action = 'Pass Through', @modifier = 'bdavis'
