# /kb — Brain query (SQLite)

The brain is the compiled graph over every structured source in the repo
(`docs/knowledge-engine.md`). It exists as JSON (`app/brain.json`, generated by
`scripts/gen-brain.py`) and SQLite (`app/brain.db`, derived/untracked).

## Status — dormant by design

SQLite is **not used** by the portal, CI, or runtime today; `app/brain.json` is
the source of truth. These tools keep the option open for when the JSON grows
unmanageable — `brain.db` is gitignored and built on demand:

```bash
make brain-db                                  # seed / migrate-in (json -> db)
python3 scripts/brain-sqlite.py dump           # migrate-out (db -> json)
python3 scripts/brain-sqlite.py query "<SQL>"  # read
python3 scripts/brain-sqlite.py exec  "<SQL>"  # write / CRUD
make check-brain-db                            # verify the round-trip is lossless
```

## Schema

- `node(id, kind, label, derived, durability, status, owner, source_path, json)`
  — kinds: Database, Table*, Field, Decision*, OpenQuestion*, ActionItem, Risk,
  Session, Workstream, Story, Deliverable, Document, Memory, Concept/Person/
  Organization/Technology/Time (KG). `json` holds the full node.
- `edge(id, src, dst, type, class, json)` — `class` is `structural` or `semantic`.
- `node_fts(id, label, kind, headings)` — FTS5 full-text index.

## Query

```bash
python3 scripts/brain-sqlite.py query "<SQL>"     # prints rows as JSON
# or directly:
sqlite3 app/brain.db "<SQL>"
```

Examples:

```sql
-- full-text search
SELECT id, kind FROM node_fts WHERE node_fts MATCH 'megatron';

-- action items and the session they arose in
SELECT n.label, e.dst FROM edge e JOIN node n ON n.id = e.src WHERE e.type = 'arose-in';

-- CDP fields and whether they resolve to a physical column
SELECT label, status, json_extract(json,'$.data.resolved') AS resolved FROM node WHERE kind='Field';

-- neighbors of a node
SELECT type, dst FROM edge WHERE src = 'db:megatron';
```

## Notes

- Read facts from their canonical owner (`docs/source-of-truth.md`); the brain is
  a generated projection — it relates data, it does not own it.
- For semantic graph traversal (neighbors, paths, clusters over the KG), prefer
  `/kg` (Planopticon), which also reads `app/knowledge_graph.json` or a `.db`.
- D1 (edge-deployed brain) is specced but gated — see the commented block in
  `wrangler.toml`. Enable only when server-side/agent queries need it.
